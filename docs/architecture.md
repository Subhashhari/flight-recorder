# Architecture

## System

**PolicyDesk** (the subject) is a 5-agent internal help-desk assistant for the synthetic company Northwind Labs, built
with Google ADK. **Flight Recorder** (the product) records, replays, branches, stress-tests and evaluates it.

```
Local machine (Docker Postgres + uv)                               GitHub Pages (static)
┌──────────────────────────────────────────────────────────┐      ┌──────────────────────┐
│ CLI → executor.execute() → ADK Runner → SequentialAgent  │      │ React UI + demo-data │
│   planner → researcher → operator → writer → verifier    │      └───────────▲──────────┘
│   every LlmAgent has Recorder callbacks                  │                  │ export-static
│     ├─ Limiter.acquire(model, est_tokens)                │                  │
│     ├─ live / replay / branch / chaos behaviour          │──────────────────┘
│     └─ buffered events → Postgres (runs, events, scores) │
│ FastAPI on 127.0.0.1:8000 serves the same UI (api mode)  │
└───────────────┬──────────────────────────────────────────┘
                ▼
        Gemini API (free tier)
```

| Agent | Tools | Writes state key |
|---|---|---|
| planner | none | `plan` (one line: `needs_policy=…; needs_action=…; employee_id=…; task=…`) |

## Replay semantics

Every event has a global `seq` and a per-`(agent, kind)` `ordinal`.

- **replay**: each LLM/tool call is served from the source run's event with the same `(agent, kind, ordinal)`. If the
  `request_hash` differs, a `divergence` event is emitted, the cached response is still served, and the run status is
  `diverged`. The limiter is never called, so a replay makes zero API calls and works with `GOOGLE_API_KEY=dummy`.
- **branch(N)**: events with `seq < N` come from cache; from `N` on, LLM calls are live (overrides applied) and tools
  execute for real. The new run stores `parent_run_id` and `branch_seq`. Allowed overrides: `model`, `temperature`,
  `instruction_append: {agent: text}`.
- **chaos**: a live run with one fault armed; it fires on the first matching call, once. Pre-execution faults
  (timeout, HTTP 500, malformed, empty) are returned by `before_tool` without running the tool; result-mutating faults
  (missing fields, retrieval empty / irrelevant / prompt injection) are applied in `after_tool` and the original result
  is kept in the event's `request._original_response`.
- Request hashes ignore per-call identifiers (`id`, `thought_signature`) so a faithful replay never looks divergent.
- Recorder callbacks are idempotent: `before_*` either serves (and records) a cached/faulted result or registers a
  `pending` entry; `after_*` records only when a `pending` entry exists.

## Overhead accounting

`recorder_self_ms` is time spent inside recorder code, excluding limiter waiting (tracked separately as
`throttle_ms`). LLM latency is measured after the limiter releases the call. Run `latency_ms` = wall time − throttle.

## Schema

See [`src/flightrec/schema.sql`](../src/flightrec/schema.sql): `chunks` (768-d `vector`, generated `tsvector`),
`query_embeddings`, `quota_usage`, `employees`, `tickets`, `expense_claims`, `runs`, `events`, `scores`.
All statistics filter `status IN ('ok','diverged','budget_exceeded','crash')`; `rate_limited` and `paused` runs are
never counted.
